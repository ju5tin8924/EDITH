Section 1 Architectural Diagrams & Infrastructure Topology

EDITH employs a Zero-Redis Dual-Database Sovereign Architecture. This model strictly segregates the transactional System of Record (SoR) from the read-heavy, low-latency Search and Entity Resolution Engine, ensuring zero write contention, high availability, and sub-second deterministic screening.

MOD-SCRN-CORE Multi-Pass Screening & Entity Resolution

Implements the algorithmic 5-pass lifecycle: Normalization, DisMax broad retrieval, phonetic Double Metaphone, and composite multi-attribute scoring:

Score = (0.60×Name) + (0.15×DOB) + (0.15×ID) + (0.10×Nat)

Includes dedicated schemas for Individual, Corporate (Trade License, Tax ID), and Maritime Vessel (IMO, MMSI, Flag State) personas.

MOD-CASE-WORK Investigation Engine & 4-Eyes Governance

Enforces strict Maker-Checker segregation of duties:

  • Analyst: Investigates hits, adds categorized notes (Investigation, Supervisor, Rationale), and escalates to PendingApproval.
  • MLRO: Reviews escalated dossiers and executes final disposition (ClearedFalsePositive or ReportedStrFreeze).
  • Collision Prevention: Pessimistic lease locking blocks competing analyst edits with 409 Conflict (15m, 30m, 1hr renewals).

Section 3 Comprehensive Catalog of All 18 Active Compliance Workflows

The EDITH platform operationalizes compliance through 18 distinct, interconnected workflows spanning real-time payment clearing, manual investigations, automated ingestion, regulatory reporting, and WORM audit verification:

1. User Onboarding, Crypto Password Provisioning & TOTP 2FA Workflow IAM SECURITY
Enforces zero-trust operator access control with mandatory password rotation and RFC 6238 TOTP two-factor authentication.
  1. Administrator provisions user in IamAccessView.tsx; CryptoPasswordGenerator.cs generates temporary high-entropy credentials.
  2. Welcome email dispatched via IEmailNotificationService.cs; user accesses /onboarding.
  3. User completes mandatory password change and scans QR code to activate TOTP 2FA via ITotpService.cs.
2. Dynamic RBAC Menu Entitlement Workflow ACCESS CONTROL
Dynamically tailors the workstation navigation tree based on tenant-scoped user group permissions.
  1. Administrator configures group permissions in /settings/menu-mappings.
  2. IEntitlementsService.cs resolves authorized menu trees from PostgreSQL core.group_menu_permissions.
  3. Sidebar.tsx dynamically filters and renders only permitted navigation groups and views.
3. Real-Time Synchronous Pre-Clearance Screening Workflow <150ms SLA | CBS INTEGRATION
Enables instant payment clearance for real-time payment rails (UAE IPP, SEPA Instant, FedNow) with evaluate-and-hold guarantees.
  1. Core Banking System (CBS) sends POST /api/v1/screen/transaction with an Idempotency-Key header.
  2. Gateway validates JWT and routes payload to Edith.Screening.Core.
  3. 5-pass screening evaluates Sender, Beneficiary, and Intermediary against OpenSearch 2.12 inverted indices.
  4. Clean (<80%): Returns HTTP 200 CLEARED with digital clearance memo token in under 150ms.
  5. Match Hit (≥80%): Returns HTTP 200 HELD, auto-provisions an investigation case in cases.aml_cases, and locks the payment ledger.
4. Universal Single Entity Name Search & In-Line Adjudication Workflow ANALYST WORKSTATION
Interactive compliance lookup for ad-hoc customer onboarding and suspicious counterparty checks.
  1. Compliance officer selects target persona mode (Individual, Corporate, or Vessel) in NameSearchView.
  2. System queries OpenSearch indices using Double Metaphone and 3–10 edge n-grams.
  3. Candidate hits display ranked match percentages, token highlight breakdowns, and sanction program tags.
  4. In-Line Adjudication Slip: Analyst can dismiss false positives or escalate into a formal case with 1 click.
  5. Onboarding Clearance Memo: For clean searches, generates a verifiable digital clearance memo with operator timestamp.
5. Interactive "What-If" Sensitivity Simulation Workflow THRESHOLD CALIBRATION
Empowers compliance supervisors to simulate match sensitivity adjustments in real time without executing server queries.
  1. Analyst loads screening candidate matches in the compliance console.
  2. Officer drags the interactive What-If Slider (50% to 95%) across the candidate dataset.
  3. Client-side engine instantly re-filters, re-ranks, and updates match badges in real time.
  4. Supervisors evaluate false-positive impact before submitting formal threshold adjustment requests to IT.
6. Batch Multi-Line Clipboard Paste Screening Workflow HIGH-VELOCITY SCREENING
Rapid ad-hoc screening of unstructured text or multi-column data directly copied from spreadsheets or emails.
  1. Operator pastes multiple lines of raw text (names, IDs, nationalities) into the batch text area.
  2. Client-side parser tokenizes and validates each line into discrete entities.
  3. Entities are dispatched asynchronously in parallel batches to the screening engine.
  4. Results appear in a consolidated table displaying line-by-line match scores, hit badges, and summary statistics.
7. Streaming Bulk File Ingestion, Deduplication & Skipped Export Workflow MOD-SCRN-BULK
High-capacity ingestion of massive sanction watchlists and customer portfolios without memory exhaustion.
  1. User uploads large CSV, XML, or JSON watchlist or customer files via BulkScreeningView.
  2. AmlStreamingParser streams records via .NET 10 IAsyncEnumerable within bounded memory buffers.
  3. Engine standardizes attributes into the 9-field AML schema and verifies uniqueness against PostgreSQL.
  4. Existing records are skipped; skipped records are retained when keepSkipped=true.
  5. SignalR streams real-time ingestion progress (rows/sec, hits); user downloads skipped duplicates in CSV, JSON, or XML.
8. Periodic Watchlist Delta Rescreening Workflow AUTOMATED RESCREENING
Automated customer portfolio re-screening following the publication of new international or local sanctions lists.
  1. New sanction feeds (UN, OFAC, UAE Local Terrorist List) are ingested into edith_watchlist_v1.
  2. System triggers an asynchronous delta comparison between updated watchlists and active customer profiles.
  3. Differential change-detection flags only newly affected accounts, suppressing unchanged historical matches.
  4. Generated alerts are routed directly to the designated compliance review queue.
9. 4-Eyes Maker-Checker Case Investigation & Pessimistic Lease Workflow MOD-CASE-WORK | GOVERNANCE
Strict segregation of duties for suspicious transaction investigation and formal resolution.
  1. Screening hits auto-provision an Open case in cases.aml_cases.
  2. Analyst Lock: Analyst opens the case and acquires an atomic 15-minute lease lock (with 15m, 30m, 1hr renewals); other analysts receive 409 Conflict.
  3. Triage: Analyst examines side-by-side PEP diffs, records categorized notes, and escalates to PendingApproval.
  4. MLRO Approval: Compliance Officer reviews dossier and adjudicates: ClearedFalsePositive or ReportedStrFreeze.
  5. Case resolves, lease releases, and audit ledgers record state transition with SHA-256 block hash.
10. Core Banking Signed Webhook Callback Workflow MOD-EVENTS-CBS | CBS INTEGRATION
Cryptographically signed automated ledger callbacks notifying core banking systems of final compliance dispositions.
  1. MLRO adjudicates case in EDITH Workstation.
  2. ICbsWebhookDispatcher constructs signed JSON callback (RELEASE or FREEZE).
  3. Calculates HMAC-SHA256 signature using CBS shared secret and attaches X-Edith-Signature header.
  4. Dispatches callback via Polly retry policy (exponential backoff across 3 attempts with jitter).
  5. Permanently unreachable endpoints record undelivered payload to notifications.delivery_ledgers for reconciliation.
11. Regulatory STR / SAR `goAML` Reporting Workflow MOD-GOAML-GCC | COMPLIANCE REPORTING
End-to-end generation and filing of Suspicious Transaction Reports adhering to UNODC goAML v5.0 standards.
  1. Case adjudicated as ReportedStrFreeze initiates regulatory reporting workflow.
  2. GenAI Narrative Copilot (MOD-AI-NARR) synthesizes case telemetry into a structured 5-section STR narrative.
  3. Engine maps transaction details, counterparties, and entity profiles into official UNODC goAML v5.0 XML schema.
  4. Compliance officer reviews generated STR package and downloads XML payload for upload to the national FIU portal.
12. Customer KYC 360 & UBO Tree Cascade Screening Workflow CUSTOMER INTELLIGENCE
Visualizes beneficial ownership structures and performs 1-click simultaneous screening across corporate entities and all UBOs.
  1. Analyst opens corporate customer profile in /kyc360.
  2. Visualizes multi-tier UBO equity ownership hierarchy tree with equity percentages and PEP status.
  3. Clicks 1-Click Cascade Screening; system parallel-screens the legal entity, TRN, and all UBOs against watchlists.
  4. Consolidated clearance matrix flags sanctioned owners and auto-updates the customer's risk profile.
13. Interactive OCR Document Inspection & EDD Sign-off Workflow DOCUMENT VERIFICATION
Inspects identity documents with bounding boxes and tracks statutory Source of Wealth (SoW) corroboration.
  1. Analyst opens passport or trade license in /kyc360 document vault.
  2. OCR Inspector renders extracted JSONB fields, per-field confidence scores, and visual bounding boxes.
  3. Analyst verifies statutory SoW/SoF corroboration checklist items and signs off periodic EDD review.
  4. Generates a WORM-sealed Customer EDD Audit Dossier with SHA-256 block hash.
14. Whitelist Exemption & False-Positive Suppression Workflow ALERT REDUCTION
Controlled false-positive suppression with strict approval hierarchies and mandatory expiry dates.
  1. Authorized officer identifies verified false-positive match during screening or case review.
  2. Officer opens Whitelist Modal, specifies match criteria, legal justification, and expiration date.
  3. Record is written to screening.whitelists and audited via SHA-256 block ledger.
  4. Subsequent screening evaluations matching whitelist criteria are suppressed automatically (returning CLEARED).
15. AML Rule Authoring, Category Form Editor & Shadow Execution Workflow MOD-RULE-PROC
Category-aware rule composition, velocity anomaly detection, and shadow-mode execution.
  1. Compliance admin authors new transaction monitoring rule in RuleBuilderView.
  2. Configures parameters via category form editor (High-Risk Corridors, Structuring/Smurfing, Velocity Anomalies).
  3. Pre-save draft backtest evaluates sample triggered transactions against recent transaction logs.
  4. Administrator stages rule in SHADOW mode to monitor alert velocity before live promotion.
16. 50,000-Record Portfolio Backtesting Sandbox & Calibration Workflow THRESHOLD CALIBRATION
Replays historical transaction archives to calculate Sensitivity Elbow Curves and auto-balance scoring weights.
  1. Officer adjusts composite scoring sliders with auto-balance and pin-locks in RuleSandboxView.
  2. Initiates high-speed simulation against a 50,000-record historical transaction archive.
  3. System calculates Baseline Delta, Ground-Truth STR Recall, and 5-point Sensitivity Elbow Curve.
  4. Officer promotes optimal threshold to active configuration with WORM SHA-256 audit logging.
17. All 14 Regulatory PDF Reports & 16-Field Query Workflow REGULATORY COMPLIANCE
Generates and exports all 14 official regulatory reports with 16-field multi-parameter query filtering.
  1. Officer selects target report from Section 4e Reports, Section 4f Log Reports, or Cross-Module Reports.
  2. Applies progressive 2-tier filter bar covering all 16 transaction attributes.
  3. 3-day EDD & 7-day SLA auto-escalation watchdog flags approaching central bank statutory deadlines.
  4. Exports self-auditing CSV/JSON bundles or generates printable Certified Regulatory Examination Reports.
18. WORM Cryptographic Audit Chain & Verification Workflow MOD-DB-STORE | AUDIT INTEGRITY
Immutable, tamper-evident audit logging fulfilling central bank examination and forensic standards.
  1. Every state change writes to core.audit_ledgers chained to previousBlockHash via SHA-256.
  2. Auditor opens /reports and clicks Verify WORM Cryptographic Chain.
  3. Engine validates hash chain continuity from Genesis Block through every live transaction event.
  4. Outputs cryptographic attestation certificate verifying zero tampering across the audit ledger.
